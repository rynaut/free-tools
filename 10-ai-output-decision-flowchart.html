Should I Accept This AI Output?

A 7-gate decision framework for engineers, PMs, and reviewers. Run every AI-generated output through this before it ships or acts on your behalf.

AI outputs that look correct are not always correct. The gap between plausible and accurate is where production incidents live. This framework is a 2-minute gate — not a substitute for domain expertise, but a structured check that catches the failure modes humans most often miss.

Accept — all gates passed
Revise — fix before accepting
Hold — needs human approval
Reject — do not use
START
You have an AI-generated output in front of you.
Apply this framework before accepting, acting on, or shipping it.
↓
GATE 1 · GROUNDING
Can every factual claim be verified against a known source?
Numbers, names, citations, API names, dates, URLs — anything checkable.
YES → Gate 2
NO →
REVISE
Flag unverified claims. Verify or remove before accepting.
↓
GATE 2 · SCOPE
Does this output stay within scope — no added assumptions or unsolicited decisions?
AI models often solve an adjacent problem or make implicit decisions the user didn't request.
YES → Gate 3
NO →
REVISE
Strip additions outside original scope. Rerun with a tighter prompt.
↓
GATE 3 · CONSEQUENCE
Is the blast radius of acting on this output low — meaning a mistake is cheap to reverse?
Sending email, deploying code, deleting data, and publishing content all have different reversal costs.
YES → Gate 4
NO →
HUMAN REVIEW
High-consequence outputs require a human in the loop. Add an approval step.
Zero Blast Radius principle: if you can't reverse it fast, don't automate the final step.
↓
GATE 4 · CONSISTENCY
Does this output match what the same model produced last time for a similar input?
Inconsistency signals model drift, prompt regression, or context pollution.
YES → Gate 5
NO →
INVESTIGATE
Check prompt, context window, and model version before proceeding.
↓
GATE 5 · BIAS & SAFETY
Is this output free of harmful bias, discriminatory framing, or legal/reputational risk?
Customer-facing, hiring, legal, and medical outputs carry the highest risk surface.
YES → Gate 6
NO →
REJECT
Do not accept. Rewrite with explicit constraints. Log the failure pattern.
↓
GATE 6 · COMPLETENESS
Does this output fully address the task — no missing steps or partial answers presented as complete?
Partial completion presented as done is more dangerous than an obvious failure.
YES → Gate 7
NO →
REVISE
Identify missing elements. Prompt for gaps rather than accepting an incomplete answer.
↓
GATE 7 · OWNERSHIP
Can a named human take responsibility for the accuracy and consequences of this output?
If no one would put their name on it, it is not ready to ship.
YES → All gates passed
NO →
HOLD
Do not ship AI output without an accountable owner. Assign ownership first.
↓
✓ ACCEPT
All 7 gates passed. This output is cleared for use.
Log it. If customer-facing, keep a copy of the original output and the gates it passed. This is your audit trail.
